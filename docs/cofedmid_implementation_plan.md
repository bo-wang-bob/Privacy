**2. 主要思路与三个模块**

论文关注一部分客户端需要防御的场景：这些客户端组成可信联盟，其他客户端照常训练。攻击者是遵守协议但试图推断成员身份的服务器或其他客户端；联盟协调者只需要类别编号、聚合权重相关信息和噪声协调信息，不需要原始样本或完整客户端模型。

关键问题是跨轮记忆。样本随着训练反复暴露，其损失、置信度和梯度轨迹可能逐渐区别于非成员。非成员又分为完全不属于 FL 系统的 OFL，以及属于其他客户端训练集的 IFL；只缩小成员与 OFL 的差异，可能仍然留下成员与 IFL 的差异。

| 模块 | 论文机制 | 作用 |
|---|---|---|
| 类别引导划分 | 每轮给联盟客户端分配随机变化、尽量少重叠的类别子集；类别数随训练衰减 | 限制本地数据暴露，同时让联盟共同学习不同类别 |
| 效用补偿 | 用 EXP3 选择损失难度区间，回收一部分未被类别划分选中的本地样本；对回收样本增加置信度正则 | 恢复任务效用并限制回收样本的过度自信 |
| 聚合中性扰动 | 给联盟上传加入满足真实权重下加权和为零的噪声 | 干扰服务器看到的单客户端信号，同时保持该轮全局聚合结果 |

类别数的线性衰减写作：

\[
m_t=\max\left(m_{\min},m_{\max}-\frac{m_{\max}-m_{\min}}{T-1}(t-1)\right).
\]

效用补偿首先用模型对本地训练集逐样本计算损失、做 min-max 归一化并建立难度区间。EXP3 选择一个区间，回收其中不在当前分配类别内的样本；超过回收上限时随机抽取。奖励采用独立验证集上本轮训练前后的平均损失下降，再根据历史奖励的 20/80 分位归一化。它不是为每个候选重新训练一个反事实模型。

对回收样本，令模型真实类别置信度为 \(p_y\)，软目标设为 \(q_y=\operatorname{stopgrad}(p_y)\)，其余类别均分 \(1-p_y\)。按论文训练目标实现时，全部入选样本参与 CE，回收样本额外参与 \(\mathrm{KL}(q\Vert p)-\mu H(p)\)。PyTorch 应明确使用 `kl_div(log_p, q)` 的方向与 reduction。不能沿用没有声明的置信度截断或混淆 KL 两个方向。

聚合中性条件为：

\[
\delta_k=\delta'_k-\frac{w_k}{\sum_j w_j^2}\sum_j w_j\delta'_j,
\qquad \sum_{k\in C}w_k\delta_k=0.
\]

论文描述每个客户端的标量噪声施加到统一参数向量尾部的一段坐标。噪声不抵消前两个模块造成的训练变化，只保证固定一组本地训练结果之后，增加模块三不改变其加权聚合。该方法是经验性 MIA 防御，不提供 DP 的 epsilon 保证。

**5. 推荐的 FedSGD 适配语义**

首版保留模型基线的 IID/few-shot 设置、学习率、通信轮数、batch size 上限、one-batch 和 uniform 聚合。

每轮先在客户端本地形成 `assigned_indices` 与 `recycled_indices`，取并集作为该轮可训练池，再从中无放回抽取至多一个配置大小的 batch。回收上限按客户端完整本地训练集计算，与论文一致；真正进入这一 batch 的回收样本才参与梯度和置信度正则。每轮恰好一次 optimizer step，记录所有实际样本索引。

这一选择需要明确实验解释：原论文的完整 local epoch 会因可训练池缩小而减少优化步数；one-batch FedSGD 在可训练池足够大时仍消费同样数量的样本。因此首版保留了类别协作、回收和消噪机制，但不能预先断言保留了相同程度的“减少总训练暴露”。必须记录累计样本使用次数和独立样本覆盖率；若防御不足，再单独设计降低每轮实际 batch 数量的消融，避免静默改变主协议。

空可训练池不能偷偷回退到高损失样本或整个训练集。默认在可行性检查或首次出现时明确报错，记录缺失类别；有需要时再增加显式、可统计的回退策略。池不足一个完整 batch 时使用真实较小 batch，并据实际 N 构造审计候选。

模块三直接作用于上传梯度：

\[
G'_k=G_k+\xi_k,\qquad\sum_{k\in C}w_k\xi_k=0.
\]

若噪声强度定义在论文的参数扰动空间，应使用 \(\xi_k=-\delta_k/\eta_t\)，使可观察的 post-state 恰为 \(\theta_t-\eta_tG_k+\delta_k\)。梯度空间标准差和参数空间标准差必须用配置字段区分；不能将 ResNet18 的 0.1 直接当作所有 PEFT 模型的梯度噪声默认值。需检查学习率接近零时的数值范围。

聚合、`protocol_messages`、梯度观察回调和攻击器都读取同一份防御后上传。客户端用于 EXP3 奖励的训练后模型保留为本地信息，不得作为服务器攻击输入。冻结主干不加噪；LoRA 的 A/B 分别保持同名因子上传。参数掩码必须在全部联盟成员间一致，并明确顺序与尾部范围，不能让每个成员独立选坐标。

首版要求联盟至少两个成员且每轮完整参与。后续支持掉线时，按实际参与联盟与最终聚合权重重新投影；只有一个联盟成员时无法生成非零且聚合中性的独立上传噪声，必须明确处理。私有掩码随机状态不作为服务器可见信号或普通 run_config 的可恢复秘密；可复现实验模式需明确威胁模型。

**6. 数据和审计协议必须同步处理**

1. 为补偿模块增加独立 `defense_validation` 数据视图。默认从原独立 evaluation 分区确定性分层预留，保留原训练集和 few-shot 数量；最终任务评估和审计非成员使用剩余部分。预留比例和索引写入数据清单，验证前先检查每类剩余容量。
2. `none` 对照任务采用同一份预留清单、同一训练划分和候选来源，保证可比较。原有未预留的历史结果不能直接充当这个对照。其他任务在未启用该实验配置时保持原数据协议。
3. 固定候选的成员定义仍是目标客户端完整原始训练集；增加“只参与难度评分、实际参与过梯度、累计使用次数、回收次数”等审计附加分组。未被选中训练的成员不重新标为非成员。
4. 真实 Batch 候选严格来自实际参与梯度计算的 batch，并保留稳定本地索引及 assigned/recycled 标记。非成员继续从未训练且未用于防御奖励的池中按标签抽取 10N；容量不足时明确报告。
5. 现有五种固定攻击用于与当前实验衔接。论文额外评估 FTA-L 和 SeqMIA：本仓库的 `fta_measurement: loss` 可形成单独的 FTA-L 运行，但不能与默认 confidence 结果合并；SeqMIA 尚不属于 11 种正式攻击，完整论文评估需要独立扩展任务。
6. 论文同时关心 IFL/OFL。首版主指标保持当前 OFL 协议；完整论文验证时增加独立、明确标识的 IFL 视图，不能把其他客户端训练样本塞进要求“从未训练”的 exact-batch 非成员池。区分联盟内其他客户端与未防御客户端的 IFL 来源。
7. 当前攻击主路径观察目标客户端上传。要声称同时验证了论文的客户端侧/全局模型防御，还需要额外的 global-model 观察视图；首版只报告实际实现的威胁模型。
8. ProjRes 继续对实际上传打分，补充 `exact_batch`、`upload_perturbed`、`training_loss` 等分开的元数据，复核 `paper_fedsgd_exact`，避免仅凭 aggregator 名称就宣称满足无扰动论文推导。论文的尾部噪声可能完全不覆盖当前 ProjRes 攻击的首层参数；不能预先承诺它对 11 种攻击都有效。

防御采用置信度正则后，候选梯度攻击默认仍使用原 CE 定义。若评估了解防御的攻击者，可另加匹配防御损失的梯度分数作为明确的适应性变体。联盟上传求和会抵消模块三，因此还应验证联盟聚合观察下模块一、二留下的保护效果。

**8. 验证设计与完成标准**

- 算法不变量：联盟外客户端不受影响；类别覆盖与重叠符合所选策略；2/5/15/30 成员规模没有指数枚举；无原始数据或损失上传给协调者。
- 数据边界：防御验证集与训练集、任务评估集、两个非成员池无交集；共享清单使 none/cofedmid 对照保持一致；稳定索引穿过图像、特征、文本 collate 不丢失。
- 训练协议：每客户端每轮一个 optimizer step、一次梯度捕获；batch 中全部样本均参与损失；评分过程用 eval/no_grad 且不更新 BatchNorm 等状态；模型训练模式在评分后恢复。
- 损失与 EXP3：手算小例子核对目标概率和梯度；空回收集合正常；相同损失、分位重合、空臂、极端奖励均有限。二分类时该软目标等于当前预测，KL 梯度退化为零，需验证并如实记录，不能把该项当作额外的有效正则证据。
- 噪声中性：固定本地梯度，比较模块三开/关的聚合结果，覆盖 uniform 和不等样本权重、多个张量、不同 dtype；检查全局参数掩码而非每张量单独尾部。用相对/绝对误差容限验证抵消。
- 观察一致性：聚合输入、protocol 消息、观察回调和审计分数来自同一防御后梯度；原始梯度不进入正常攻击缓存。检查只扰动上传、不反向影响奖励计算。
- 审计：真实 batch 与候选成员完全一致，10N 标签直方图正确；固定成员保持原客户端训练集定义；低 FPR 指标按样本量报告可解析性。
- 性能：记录全本地损失扫描、验证前后前向、攻击梯度计算各自耗时和峰值内存。优先复用冻结 CLIP 特征、共享更新前验证结果、流式处理本地分数；任何降低扫描频率的优化都单独标记为算法变体。

真实试跑顺序建议为 CLIP-MLP/Caltech101 → CLIP-Adapter 与 CLIP-LoRA → BERT Adapter/LoRA → GPT2 Adapter。最小端到端试跑应跨过回收启动轮，例如先跑 12 轮；正式实验恢复各模型原定通信轮数。

每个代表性设置至少比较 `none`、仅模块一、模块一+二、完整三模块，并加入仅模块三的聚合中性检查；全客户端联盟为默认主设置，Half/Pair 可通过显式客户端列表做后续覆盖策略对照。先以少量 seed 验证执行，再用多个固定 seed 评估效果。报告 accuracy/MCC、AUC、TPR@1%FPR、可解析时的更低 FPR、训练/审计时间、样本暴露率和类别条件指标。

实现涉及共享审计器、候选和聚合后，应按仓库约定运行完整本地套件；开发中先运行直接相关测试及 `git diff --check`。所有真实实验写入新的单任务目录，沿用 `run_config.yaml`、`run.log`、`training_metrics.csv`、`privacy_audit/` 和 `defense_summary.json`，新增 CoFedMID 轮次统计放在同一任务中。

完成标准是六个 PEFT 模型逐项通过入口干运行、协议与候选测试、最小端到端执行，并取得防御前后可比的效用/隐私结果。仅配置可解析、噪声抵消或攻击 AUC 降低其中一项，均不足以宣称整个论文防御已复现。
