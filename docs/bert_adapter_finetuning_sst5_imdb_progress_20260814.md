# BERT Adapter 联邦微调方式与 SST-5/IMDb 实验进展

## 技术摘要

- 当前 BERT 实验不是全参数微调，而是在冻结的 `bert-base-uncased` 每个 Transformer block 后插入一个 ratio-2 bottleneck Adapter，并额外训练任务分类头；可训练参数约 709 万，冻结主干约 1.095 亿。
- 联邦训练采用 30 个 IID 客户端全部参与的同步 one-batch FedSGD。每轮每客户端只使用一个 batch（16 条样本）做一次无动量 SGD 更新，服务器对 30 个客户端上传等权平均；当前学习率恒定为 `0.001`，共 500 轮。
- SST-5 最终 accuracy 为 **29.34%**，高于 26.25% 多数类基线，但第 350–500 轮提升已经放缓；当前配置能够学习，尚未达到很强的五分类效果。
- IMDb 最终 accuracy 为 **64.42%**，从训练前的 49.70% 持续上升，直到第 500 轮仍没有明显平台；这是目前更适合继续增加轮数或测试更大学习率的任务。
- 相比相同 batch/轮数下的 `lr=0.0001` 批次，`lr=0.001` 使 SST-5 提高 **2.45 个百分点**、IMDb 提高 **10.68 个百分点**，证明此前 BERT 的主要问题之一是优化步长不足。
- 通用 record-level 成员推理仍接近随机，但观察真实当轮上传 batch 的严格 ProjRes 仍然较强；普通任务效用和两类隐私攻击应继续分开解释。

## BERT 只训练 Adapter 与分类头

当前模型以本地 `bert-base-uncased` checkpoint 为冻结主干。BERT 有 12 个 Transformer block、hidden size 为 768；每个 block 的输出后插入一个残差 Adapter：

```text
输入文本
  │
  ├─ Tokenizer：最大长度 128
  │
  ▼
冻结的 BERT Transformer block（×12）
  │
  ▼
可训练 Adapter：768 → 384 → ReLU → 768
  │               down             up
  └────────────── residual addition ──────────────┐
                                                   │
                      重复 12 次                    │
                                                   ▼
冻结的 BERT pooler → 可训练线性分类头 → 类别 logits
```

每个 Adapter 的前向计算为：

\[
h' = h + W_{up}\,\mathrm{ReLU}(W_{down}h+b_{down})+b_{up}.
\]

ratio-2 表示 bottleneck dimension 为 `768 / 2 = 384`。12 个 Adapter 合计包含 7,091,712 个参数；分类头随任务类别数变化：

| 任务 | 分类头 | 分类头参数 | 总可训练参数 | 冻结参数 |
|---|---|---:|---:|---:|
| SST-5 | `Linear(768, 5)` | 3,845 | 7,095,557 | 109,482,240 |
| IMDb | `Linear(768, 2)` | 1,538 | 7,093,250 | 109,482,240 |

当前 `zero_init_up: false`，Adapter 的 down/up projection 都使用 BERT initializer range 对应的 `N(0, 0.02²)` 小随机初始化；分类头同样随机初始化。BERT 主干保持冻结，冻结主干中的 dropout 在本实现里被关闭，任务头 dropout 配置为 0。

**含义：**每个客户端上传的是 Adapter 和分类头的更新，不包含冻结 BERT 主干。这样显著减少了每个客户端需要保存和通信的可训练状态，但 ratio-2 Adapter 本身仍有约 709 万参数，不属于极小规模的 Adapter。

## 联邦协议等价于大批量的一步同步 SGD

最新完成任务的统一训练协议如下：

| 项目 | 当前设置 |
|---|---|
| 客户端划分 | 固定 seed 的 IID 随机等量划分 |
| 客户端数量 | 30 |
| 每轮参与 | 30/30，全部参与 |
| 本地训练 | 每客户端每轮一个 mini-batch、一次 optimizer step |
| 本地 batch size | 16 |
| 优化器 | vanilla SGD，momentum 0，weight decay 0 |
| 学习率 | 恒定 `0.001` |
| 梯度裁剪 | 关闭，`max_grad_norm: 0` |
| 服务器聚合 | uniform FedSGD，30 个客户端等权 |
| 通信轮数 | 500 |
| 普通任务评估 | 训练前一次；第 50、100、…、500 轮 |
| 隐私审计 | 六种通用攻击和 ProjRes 均每 50 轮一次 |
| 随机种子 | 42 |

每轮开始时，所有客户端从同一个全局 Adapter/分类头状态出发。客户端 \(i\) 在 batch \(B_i\) 上计算一步：

\[
\theta_i^{t+1}=\theta^t-\eta g_i^t.
\]

服务器等权聚合 30 个客户端状态：

\[
\theta^{t+1}=\frac{1}{30}\sum_{i=1}^{30}\theta_i^{t+1}
=\theta^t-\eta\frac{1}{30}\sum_{i=1}^{30}g_i^t.
\]

由于每个客户端 batch 都是 16，单轮有效训练规模约为 `30 × 16 = 480` 条样本。它接近一次 batch 480 的同步大批量 SGD，但数据仍由客户端本地 batch 产生，并保留各客户端的真实 one-batch 上传，供隐私攻击观察。

当前文本入口没有 Dirichlet 或其他正式异构设置。SST-5 每客户端约 284–285 条训练样本，IMDb 每客户端约 833–834 条；500 轮总共使用约 240,000 个样本位置，相当于约 28.1 个 SST-5 全局 epoch、9.6 个 IMDb 全局 epoch。

## SST-5 已超过简单基线，但后期接近平台

SST-5 使用 8,544 条训练样本和 1,101 条 validation 样本，任务是五分类情感分析。下图左列显示，第 50 轮已经从随机任务头的 21.98% 上升到 26.79%，之后缓慢提高到第 500 轮的 29.34%。

![BERT 在 SST-5 和 IMDb 上的普通任务进展](../analysis_scripts/bert_sst5_imdb_progress_20260814.png)

| 已完成轮次 | Accuracy | Cross-entropy loss |
|---:|---:|---:|
| 0 | 21.98% | 1.5884 |
| 50 | 26.79% | 1.5705 |
| 100 | 26.88% | 1.5691 |
| 150 | 27.70% | 1.5677 |
| 200 | 27.61% | 1.5672 |
| 250 | 27.70% | 1.5656 |
| 300 | 28.79% | 1.5629 |
| 350 | 29.06% | 1.5619 |
| 400 | 29.06% | 1.5593 |
| 450 | 28.97% | 1.5568 |
| 500 | **29.34%** | **1.5538** |

验证集多数类占比为 26.25%，最终模型高出约 3.09 个百分点。从趋势看，loss 仍持续下降，但 accuracy 在第 350–500 轮只提高约 0.27 个百分点，说明模型正在改善概率排序或置信度，分类决策已经接近当前协议的平台。

与紧邻的 `lr=0.0001` 批次相比，最终 accuracy 从 26.88% 提高到 29.34%（+2.45 pp）；与更早的 batch-32、`lr=0.001` 历史任务 29.61% 也很接近。现有证据支持保留 `lr=0.001`，但单纯把轮数继续翻倍预计只能带来有限收益。下一步更有价值的单变量实验是测试 `zero_init_up: true`，或将当前 SGD 变体与 utility-calibrated AdamW 变体分开比较。

## IMDb 在第 500 轮仍持续改善

IMDb 使用官方 25,000 条 train 和 25,000 条 test，任务为正/负二分类。图中右列显示 accuracy 几乎随每个评估点持续上升，loss 同时单调下降，没有 SST-5 那样明显的平台。

| 已完成轮次 | Accuracy | Cross-entropy loss |
|---:|---:|---:|
| 0 | 49.70% | 0.7017 |
| 50 | 53.24% | 0.6912 |
| 100 | 56.14% | 0.6888 |
| 150 | 57.88% | 0.6867 |
| 200 | 58.95% | 0.6846 |
| 250 | 60.19% | 0.6824 |
| 300 | 61.00% | 0.6802 |
| 350 | 62.61% | 0.6775 |
| 400 | 62.93% | 0.6749 |
| 450 | 63.94% | 0.6718 |
| 500 | **64.42%** | **0.6679** |

最终 accuracy 比 50% 平衡基线高 14.42 个百分点，相对训练前提高 14.72 个百分点。`lr=0.001` 相对 `lr=0.0001` 的最终 53.74% 提高了 10.68 个百分点，也超过更早 batch-32、300 轮任务的 61.87%。因此，IMDb 的最新结果更直接支持“原 `1e-4` 学习率过小”。

当前最稳妥的后续实验是保持 `lr=0.001` 延长到 1,000 轮，并使用连续多个评估点的提升幅度决定是否提前停止。若要测试 `5e-3`，应创建 IMDb 专用配置，先运行 200 轮无攻击消融，并与 `2e-3` 对照；不应直接把共享 BERT 配置的三个数据集全部改为 `5e-3`。

## 普通任务恢复后，通用攻击仍弱而 ProjRes 仍强

本项目同时追踪两种不同的成员隐私问题：

- 六种通用攻击把目标客户端训练记录定义为成员，衡量 record-level membership inference。
- ProjRes 把某一轮目标客户端真实 FedSGD batch 定义为成员，衡量当轮上传更新泄漏。

| 数据集 | 最强最终通用攻击 | 最终通用 AUC | 最终 ProjRes AUC | ProjRes TPR@0.1%FPR |
|---|---|---:|---:|---:|
| SST-5 | FedMIA-Cosine | 0.5142 | **0.9778** | 87.50%（14/16） |
| IMDb | Avg-Cosine | 0.5108 | **0.7799** | 6.25%（1/16） |

通用攻击的 AUC 均接近随机水平 0.5；SST-5 只有 37/37 个成员/非成员、IMDb 为 100/100，因此低 FPR 统计能力有限。ProjRes 使用 1,000 个非成员，但成员只有当轮 batch 的 16 条，TPR 以 6.25 个百分点为一步。两类攻击的成员定义不同，不能把 AUC 差异直接解释为某个攻击算法更优。

对当前微调决策而言，最重要的观察是：提高学习率明显恢复了 IMDb 普通任务效用，但没有让通用 record-level 攻击稳定增强；与此同时，真实 one-batch 上传仍暴露很强的 ProjRes 信号，尤其是在 SST-5 上。

## 数据、指标和验证范围

- 文档快照时间：2026-08-14（Asia/Shanghai）。截至该时间，没有比 2026-08-13 `lr=0.001` 批次更新的 BERT 任务。
- SST-5 accuracy 使用完整 validation 1,101 条样本；IMDb accuracy 使用官方 test 25,000 条样本。
- 每个最新任务都有训练前基线和第 50–500 轮共 11 个普通任务记录，训练健康检查均通过，最终参数有限且更新范数非零。
- 最新结果只有 seed 42，隐私攻击只有目标客户端 0；无法估计跨 seed、客户端和自然 batch 的方差。
- 当前结论适用于 IID、30 客户端全部参与、uniform one-batch FedSGD，不应直接外推到 Dirichlet 异构、客户端部分参与、FedAvg local epoch 或全参数 BERT 微调。

## 推荐的下一步

1. **保留 BERT 默认学习率 `0.001`。** 它已经修复 `1e-4` 下明显的优化不足。
2. **SST-5 优先做初始化消融。** 保持 batch 16、SGD 和 500 轮不变，仅比较 `zero_init_up: false/true`；若仍停在 30% 左右，再单独测试 AdamW 或分组学习率。
3. **IMDb 优先扩展训练或短测更大学习率。** 主线可先延长到 1,000 轮；`2e-3/5e-3` 应作为 IMDb 专用的 200 轮无攻击预实验。
4. **效用配置胜出后再运行完整隐私审计。** 避免为明显欠训练的配置重复计算昂贵的逐样本余弦攻击。
5. **正式结论增加重复。** 至少使用 3 个 seed、多个目标客户端，并同时报告普通任务效用、通用攻击和 ProjRes 的均值与区间。

## 尚待回答的问题

- SST-5 的平台主要来自随机非零 Adapter 初始化、vanilla SGD，还是冻结整个 BERT 主干的表达上限？
- IMDb 在 `lr=0.001` 下延长到 1,000 轮能否继续稳定提升，还是会在 500–1,000 轮之间进入平台？
- IMDb 的 `5e-3` 是否能加速早期收敛而不引起后期振荡？
- 跨 seed 和固定审计 batch 后，SST-5/IMDb 的 ProjRes 强度是否保持？
